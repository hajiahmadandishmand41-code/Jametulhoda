### Dynamic (pattern) routes

- `~^/book/(\d+)/?$~D` → `pages/book.php` ({"id":1})
- `~^/book/([^/]+)/?$~uD` → `pages/book.php` ({"slug":1})
- `~^/(post|lesson|speech|category|topic)/([^/]+)/?$~uD` → `pages/$1.php` ({"slug":2})
- `~^/lessons/([^/]+)/([^/]+)/?$~uD` → `pages/lessons.php` ({"collection":1,"volume":2})
- `~^/lessons/([^/]+)/?$~uD` → `pages/lessons.php` ({"collection":1})
- `~^/search/([^/]+)/?$~uD` → `pages/search.php` ({"q":1})

## Data model

`users`, `categories`, `topics`, `posts`, `post_images`, `post_topics`,
`lesson_collections`, `lesson_volumes`, `lessons`, `lesson_topics`,
`contact_messages`, `media_files`, `settings`, `books`, `book_topics`,
`site_banners`, `featured_banners` plus the infrastructure tables `app_sessions`,
`login_limits`, `stored_files`, `storage_deletions`, `pending_uploads`.
Roles (`superadmin`, `admin`, `editor`) apply to staff, not students.

Schema files: `database/database.mysql.sql` (MySQL 8 / MariaDB 10.6+, InfinityFree)
and `database/database.postgres.sql` (PostgreSQL 15+, Neon/CI). Both are idempotent;
`bin/migrate.php` picks the file that matches the active driver.

## Include policy

* Every include/require uses `__DIR__`; user input never selects a PHP filename.
* Root controllers use `__DIR__ . '/includes/…'`; controllers in `pages/` and
  `admin/*/` use `__DIR__ . '/../includes/…'` (or `'/../../includes/…'`).
* `router.php` sets `SCRIPT_NAME`/`PHP_SELF` to the resolved script path (menu and
  role logic rely on `basename()`/`dirname()`) and `JHD_ROUTE_PATH` to the public
  URL, which `includes/header.php` uses for `<link rel="canonical">`.
* Uploaded files are written through `storeValidatedFile()` only (folder allowlist,
  MIME/content sniffing, re-encoded images, `stored_files` journal).

## Historical note (layout before the restructure)

Public controllers lived in the web root (`about.php`, `articles.php`, `book.php`, …),
`admin/users.php` was a flat file, `admin/messages.php` duplicated
`admin/messages/index.php`, the schemas were `database.sql` / `database.mysql.sql` /
`update.sql` in the root, images were in `assets/images/`, the CLI stubs
`install.php` / `db-test.php` / `migrate-sections.php` sat in the web root, and several
`.htaccess` files were checked in without their leading dot (`admin.htaccess`,
`uploads.htaccess`, `admin/posts.htaccess`, …) so they were inert. All of these were
moved, renamed or merged — see [FILE_ROUTE_MAP.md](FILE_ROUTE_MAP.md).
